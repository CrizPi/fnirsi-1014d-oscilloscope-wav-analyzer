\begin{abstract}
This report documents the current implementation status of a desktop signal-analysis application for waveform files exported by the FNIRSI 1014D oscilloscope. The software parses binary oscilloscope captures, reconstructs visible time-domain traces, decodes configuration and automatic measurements, and exposes engineering analysis modules through a desktop interface built on Flask and PyWebView. The current version supports calibrated waveform reconstruction, trigger-aware visible-window cropping, MATH operations, FFT analysis, descriptive statistics, advanced temporal metrics, derivative and integral analysis, current estimation from passive components, total current synthesis, AC power estimation, transfer analysis between an input and output waveform, channel correlation, manual cursors, cycle analysis, PNG export, and LaTeX export. This document presents the architecture, the implemented equations, the signal-processing rationale, the current module inventory, and a practical framework for future validation with real experimental datasets.
\end{abstract}

\begin{IEEEkeywords}
oscilloscope, waveform reconstruction, signal processing, FFT, current estimation, transfer function, AC power, Flask, PyWebView, PyInstaller
\end{IEEEkeywords}

\section{Introduction}
Low-cost digital oscilloscopes are widely used in education, prototyping, maintenance, and electronics laboratories. Although such instruments often provide basic automatic measurements, their local firmware interfaces are usually limited in flexibility, storage, and export-oriented post-processing. The FNIRSI 1014D exports waveform captures as binary \texttt{.wav} files that contain enough information to reconstruct both displayed channels and a relevant subset of the acquisition metadata. A software layer can therefore extend the utility of the instrument by rebuilding the visible traces, extracting measurements, and enabling additional analysis workflows not directly available on the oscilloscope.

The present project implements that software layer as a desktop application. It is oriented toward engineering usage rather than generic media playback. The application parses the FNIRSI export structure, converts screen-domain samples into voltage-domain waveforms, aligns the visible window around the effective trigger reference, and provides a set of on-demand modules for numerical and graphical analysis. The software can run as a Python desktop application or as a packaged Windows executable.

\section{Objectives}
The current implementation is designed around the following goals:

\begin{enumerate}
    \item Decode FNIRSI 1014D waveform files and reconstruct the visible time-domain traces for channels X and Y.
    \item Recover oscilloscope configuration metadata including trigger information and built-in measurements.
    \item Preserve visual consistency between the oscilloscope screen and the software waveform display.
    \item Provide signal-processing modules that extend the original instrument capabilities.
    \item Support export workflows suitable for laboratory reports, especially PNG graphs and LaTeX tables.
    \item Package the software as a Windows desktop executable for users who do not work directly from a Python environment.
\end{enumerate}

\section{Current Project Scope}
At the time of this report, the application includes the following major capabilities:

\begin{itemize}
    \item waveform loading from FNIRSI \texttt{.wav} capture files,
    \item oscilloscope configuration decoding,
    \item automatic measurement decoding,
    \item trigger-aware visible waveform reconstruction,
    \item MATH operations between channels,
    \item FFT analysis,
    \item descriptive statistics,
    \item advanced temporal metrics,
    \item derivative and integral analysis,
    \item current estimation for resistor, capacitor, and inductor models,
    \item total current synthesis from saved current calculations,
    \item AC power computation for individual and total current,
    \item transfer analysis for $V_{\text{in}}$ and $V_{\text{out}}$,
    \item channel correlation,
    \item manual cursor measurements,
    \item cycle analysis,
    \item PNG and LaTeX export,
    \item desktop execution through PyWebView,
    \item packaging through PyInstaller and Inno Setup.
\end{itemize}

\section{Software Architecture}
\subsection{Execution Model}
The application combines a Flask server with a PyWebView desktop window. In desktop mode, the backend starts on the loopback interface and the native window loads the local URL. This design allows a web-style interface while preserving a desktop distribution model.

\subsection{State Model}
The implementation currently uses two main layers of state:

\begin{itemize}
    \item \textbf{Session state:} active settings and enabled modules are stored in the Flask session.
    \item \textbf{In-memory caches:} numerical analysis results and generated graphs are stored in memory to reduce repeated computation.
\end{itemize}

This design is effective for a single-user desktop workflow, although it also motivates future refactoring because \texttt{app.py} now concentrates a large portion of orchestration logic.

\subsection{Module Activation Strategy}
Most analysis modules are executed on demand rather than permanently recomputed. This reduces latency and makes the interface more responsive for heavier operations such as FFT, current synthesis, and graph generation.

\subsection{Frontend Update Strategy}
The interface uses server-rendered templates combined with targeted fragment refreshes for module updates. Instead of a full page re-render for every action, the backend returns only the affected panel in AJAX mode. This produces a more stable visual experience while keeping the implementation comparatively simple.

\section{FNIRSI File Decoding}
\subsection{Binary Layout}
The parser reads fixed blocks from the oscilloscope file and extracts:

\begin{itemize}
    \item vertical scale per channel,
    \item probe attenuation,
    \item coupling mode,
    \item horizontal time scale,
    \item trigger type,
    \item trigger edge,
    \item trigger channel,
    \item trigger 50\% state,
    \item instrument measurements,
    \item visible waveform data,
    \item full raw buffer data.
\end{itemize}

The current implementation uses explicit index validation and raises a custom parsing exception if configuration indexes fall outside the expected tables.

\subsection{Recovered Measurements}
The decoded measurement set includes:

\begin{equation}
\{V_{\max}, V_{\min}, V_{\mathrm{avg}}, V_{\mathrm{rms}}, V_{pp}, V_p, f, T, T_+, T_-, D_+, D_-\}
\end{equation}

These values are later used both for display and for waveform reconstruction.

\section{Visible Waveform Reconstruction}
\subsection{Why Reconstruction Is Necessary}
The waveform points stored in the FNIRSI file are not directly equivalent to voltage values. The displayed block corresponds to screen-oriented coordinates rather than already calibrated voltages. Therefore, the application reconstructs visible waveforms in physical units before applying downstream analysis.

\subsection{Sampling Frequency and Screen Time}
If the screen shows $N$ samples over a horizontal span of $T_{\text{screen}}$, the sampling frequency is estimated as

\begin{equation}
f_s = \frac{N}{T_{\text{screen}}}
\end{equation}

where

\begin{equation}
T_{\text{screen}} = N_{\text{div}} \cdot T_{\text{div}}
\end{equation}

and $N_{\text{div}} = 14$ horizontal divisions are used for the visible oscilloscope window.

\subsection{Trigger-Centered Time Axis}
The visible screen is reconstructed around a detected trigger crossing. Once the trigger sample index $n_0$ is estimated, the time axis becomes

\begin{equation}
t[n] = \frac{n - n_0}{f_s}
\end{equation}

This keeps the effective trigger reference at $t = 0$.

\subsection{Symmetric Visible Window Cropping}
To match the oscilloscope display, the current implementation crops the visible waveform symmetrically around the detected trigger sample. If the trigger sample is $n_0$ and the record length is $N$, the half-window is

\begin{equation}
h = \min(n_0, N - 1 - n_0)
\end{equation}

and the retained visible interval is

\begin{equation}
n \in [n_0 - h,\; n_0 + h]
\end{equation}

This step was introduced to prevent the software graph from showing an additional visible tail beyond the oscilloscope screen.

\subsection{Voltage Reconstruction from Screen Samples}
The software currently reconstructs visible voltages using an affine mapping constrained by oscilloscope measurement values. Let $r$ denote a screen-domain sample, and let $r_{\min}$, $r_{\max}$ be the extrema of the visible raw sequence. Let $V_{\max}$ and $V_{\min}$ be the instrument measurements for the same channel. The affine conversion is

\begin{equation}
\alpha = \frac{V_{\min} - V_{\max}}{r_{\max} - r_{\min}}
\end{equation}

\begin{equation}
\beta = V_{\max} - \alpha r_{\min}
\end{equation}

\begin{equation}
v = (\alpha r + \beta)\cdot G_p
\end{equation}

where $G_p$ is the probe factor.

This mapping is deliberately used instead of a fixed \texttt{raw = 200} zero reference because the latter can introduce visible DC offset errors when the real screen position is not centered.

\subsection{Channel-Off Handling}
If the oscilloscope measurement fields for a channel are all zero, the current implementation treats that channel as disabled and replaces its waveform samples by zero. This prevents a false trace from being rendered when a channel was not active during capture.

\section{Signal Conditioning}
\subsection{Non-Finite Value Sanitization}
The code replaces non-finite values by interpolation over finite neighbors before advanced analysis. This avoids propagation of NaN or infinity through later modules.

\subsection{Adaptive Smoothing}
The current implementation uses adaptive filtering depending on the type of signal and the target operation:

\begin{itemize}
    \item median filtering and smoothing for digital-like traces,
    \item low-pass and Savitzky--Golay filtering for analog traces,
    \item stronger derivative-oriented smoothing for capacitor and derivative calculations.
\end{itemize}

The goal is not aggressive denoising but improved stability for visually displayed traces and derivative-sensitive modules.

\subsection{Calibration}
The user can apply gain, offset, inversion, and normalization. If $x[n]$ is an input channel, the calibrated version is

\begin{equation}
\tilde{x}[n] = g_x x[n] + o_x
\end{equation}

and similarly for the second channel.

\section{Implemented Analysis Modules}
\subsection{Base Scope Measurements}
The main panel displays decoded scope settings and measurements together with the reconstructed waveform graph for channels X and Y. This view is the base reference for every other module.

\subsection{MATH Operations}
The application currently supports

\begin{equation}
X + Y,\quad X - Y,\quad X \cdot Y,\quad \frac{X}{Y}
\end{equation}

The MATH result is treated as an additional signal that can be measured and plotted.

\subsection{FFT Analysis}
The FFT module applies a one-sided real FFT on the selected signal. If $x[n]$ is the centered signal and $w[n]$ is the selected window, the transformed sequence is

\begin{equation}
X[k] = \mathcal{F}\{(x[n] - \bar{x})w[n]\}
\end{equation}

The module reports:

\begin{itemize}
    \item dominant frequency,
    \item dominant magnitude,
    \item top peaks,
    \item harmonic components,
    \item total harmonic distortion.
\end{itemize}

The THD estimate is based on the harmonic set:

\begin{equation}
\mathrm{THD}(\%) = \frac{\sqrt{\sum_{m=2}^{M} A_m^2}}{A_1}\times 100
\end{equation}

where $A_1$ is the fundamental magnitude and $A_m$ are higher-order harmonic magnitudes.

\subsection{Statistical Analysis}
For a sequence $x[n]$, the module computes:

\begin{equation}
\mu = \frac{1}{N}\sum_{n=0}^{N-1} x[n]
\end{equation}

\begin{equation}
\sigma^2 = \frac{1}{N}\sum_{n=0}^{N-1} (x[n]-\mu)^2
\end{equation}

\begin{equation}
x_{\mathrm{rms}} = \sqrt{\frac{1}{N}\sum_{n=0}^{N-1} x[n]^2}
\end{equation}

along with median, min, max, range, and peak-to-peak value.

\subsection{Advanced Temporal Metrics}
The advanced module computes:

\begin{itemize}
    \item rise time,
    \item fall time,
    \item overshoot,
    \item undershoot,
    \item slew rate,
    \item crest factor.
\end{itemize}

The crest factor is

\begin{equation}
C_f = \frac{|x|_{\max}}{x_{\mathrm{rms}}}
\end{equation}

\subsection{Derivative and Integral}
The derivative module numerically estimates

\begin{equation}
\frac{dx}{dt}\Big|_{n} \approx \frac{x[n+1]-x[n-1]}{2\Delta t}
\end{equation}

or its filtered equivalent, while the integral module uses cumulative trapezoidal integration

\begin{equation}
I[n] \approx \sum_{k=1}^{n}\frac{x[k] + x[k-1]}{2}\Delta t
\end{equation}

\subsection{Correlation Analysis}
Channel correlation is computed from

\begin{equation}
r_{xy}[\ell] = \sum_n x[n]y[n-\ell]
\end{equation}

The implementation also reports the lag corresponding to the maximum absolute correlation, which serves as a delay estimate.

\subsection{Manual Cursors}
The cursor module returns:

\begin{itemize}
    \item $t_1$, $t_2$,
    \item $V_1$, $V_2$,
    \item $\Delta t = t_2 - t_1$,
    \item $\Delta V = V_2 - V_1$,
    \item estimated frequency $f \approx 1/\Delta t$.
\end{itemize}

\subsection{Cycle Analysis}
For repetitive waveforms, the cycle module estimates cycle count, average frequency, average period, average peak-to-peak voltage, and average RMS value. This is useful when the global waveform hides cycle-to-cycle variation.

\section{Current and Power Modules}
\subsection{Current from a Resistor}
If the observed voltage corresponds to the resistor voltage $v_R(t)$, the current is

\begin{equation}
i_R(t) = \frac{v_R(t)}{R}
\end{equation}

\subsection{Current from a Capacitor}
If the observed voltage corresponds to the capacitor voltage $v_C(t)$, the current is

\begin{equation}
i_C(t) = C\frac{dv_C(t)}{dt}
\end{equation}

\subsection{Current from an Inductor}
If the observed voltage corresponds to the inductor voltage $v_L(t)$, the current is estimated as

\begin{equation}
i_L(t) = \frac{1}{L}\int v_L(t)\,dt + i_L(0)
\end{equation}

The current implementation supports three inductor initialization modes:

\begin{itemize}
    \item zero initial current,
    \item zero-mean current,
    \item manual initial current.
\end{itemize}

\subsection{Current Summary Metrics}
For the current waveform $i[n]$, the module reports:

\begin{equation}
I_{\mathrm{avg}} = \frac{1}{N}\sum_{n=0}^{N-1} i[n]
\end{equation}

\begin{equation}
I_{\mathrm{rms}} = \sqrt{\frac{1}{N}\sum_{n=0}^{N-1} i[n]^2}
\end{equation}

\begin{equation}
I_{pp} = I_{\max} - I_{\min}
\end{equation}

\subsection{Voltage-Current Phase}
The application estimates the phase between a selected voltage and current waveform from the dominant spectral component:

\begin{equation}
\phi = \angle I(f_0) - \angle V(f_0)
\end{equation}

and wraps the result into the interval $[-180^\circ, 180^\circ]$.

\subsection{AC Power Quantities}
Using RMS values and the voltage-current phase, the application computes:

\begin{equation}
S = V_{\mathrm{rms}} I_{\mathrm{rms}}
\end{equation}

\begin{equation}
P = V_{\mathrm{rms}} I_{\mathrm{rms}} \cos\phi
\end{equation}

\begin{equation}
Q = V_{\mathrm{rms}} I_{\mathrm{rms}} \sin\phi
\end{equation}

\begin{equation}
\underline{S} = P + jQ
\end{equation}

\begin{equation}
\mathrm{pf} = \cos\phi = \frac{P}{S}
\end{equation}

These quantities are reported both for the individual current analysis and for the total current synthesis module.

\subsection{Total Current Synthesis}
Saved current calculations from the current file can be resampled onto a common reference time axis and summed:

\begin{equation}
i_{\mathrm{tot}}[n] = \sum_{m=1}^{M} i_m[n]
\end{equation}

The current implementation only supports the parallel-style summation workflow. Previous multi-file and series-comparison behaviors were intentionally simplified to avoid ambiguous alignment behavior.

\section{Transfer Analysis}
\subsection{Purpose}
The transfer module compares two selected signals from the same file, interpreted as $V_{\mathrm{in}}$ and $V_{\mathrm{out}}$. This is useful for RC, RL, filter, and general source-to-load analysis.

\subsection{RMS and Peak-to-Peak Gain}
The module computes:

\begin{equation}
G_{\mathrm{rms}} = \frac{V_{\mathrm{out,rms}}}{V_{\mathrm{in,rms}}}
\end{equation}

\begin{equation}
G_{pp} = \frac{V_{\mathrm{out,pp}}}{V_{\mathrm{in,pp}}}
\end{equation}

\subsection{Gain in Decibels}
The reported gain in decibels is

\begin{equation}
G_{\mathrm{dB}} = 20\log_{10}(G_{\mathrm{rms}})
\end{equation}

\subsection{Transfer Phase}
The input-output phase is computed using the same dominant-frequency spectral method:

\begin{equation}
\phi_{vo} = \angle V_{\mathrm{out}}(f_0) - \angle V_{\mathrm{in}}(f_0)
\end{equation}

\subsection{Equivalent Time Delay}
If the dominant frequency is $f_0$, the equivalent delay is estimated as

\begin{equation}
\Delta t = \frac{\phi_{vo}}{360^\circ f_0}
\end{equation}

\subsection{Correlation Peak}
To provide an additional similarity indicator, the transfer module also reports the peak normalized correlation between the input and output waveforms.

\section{User Interface and Visualization}
\subsection{Main Graph}
The main graph displays channels X and Y using a visual configuration intended to resemble the oscilloscope view while still allowing software-side analysis and export.

\subsection{Current Graphs}
Current graphs display voltage and current together in a consistent style derived from the main graph, with the legend positioned horizontally in the upper-right area.

\subsection{Transfer Graph}
The transfer graph overlays $V_{\mathrm{in}}$ and $V_{\mathrm{out}}$ using the same main-plot style so that attenuation and phase shift can be inspected directly.

\subsection{Loading Feedback}
The current interface includes a centered loading overlay for slower operations. This was added to avoid the appearance of inactivity during server-side processing.

\section{Export and Reporting Features}
The current project exports:

\begin{itemize}
    \item PNG graphs for the main waveform, MATH, FFT, derivative, integral, current, total current, correlation, and cursor-related plots,
    \item LaTeX fragments for base measurements, MATH, FFT, statistics, advanced measures, calibration, current, total current, correlation, cursors, cycle analysis, transfer analysis, and snapshot comparison.
\end{itemize}

This makes the application useful not only as an analysis workstation but also as a reporting assistant.

\section{Current Strengths}
The most important strengths of the current implementation are:

\begin{itemize}
    \item accurate visual reconstruction of the oscilloscope screen through trigger-centered cropping,
    \item broader feature set than the original oscilloscope firmware,
    \item consistent analysis workflow across voltage, current, power, and transfer modules,
    \item desktop-friendly execution and download behavior,

\section{Known Limitations}
The current project also has several important limitations:

\begin{itemize}
    \item the codebase remains heavily centered in \texttt{app.py},
    \item the project does not yet include a formal automated test suite,
    \item some calculations still depend on filtered display-oriented signals rather than a fully separate analysis pipeline,
    \item the parser and reconstruction logic are specialized for the FNIRSI 1014D format,
    \item the local Python development environment may require repair or recreation before reproducible local builds can be guaranteed.
\end{itemize}

\section{Recommended Validation Protocol}
To convert the project into a publication-grade engineering artifact, the following validation strategy is recommended:

\begin{enumerate}
    \item Prepare reference waveform files with known theoretical values.
    \item Compare software outputs against both theory and oscilloscope readings.
    \item Include at least one sinusoidal RC or RL case for transfer-phase validation.
    \item Include at least one resistor and one capacitor case for current and power validation.
    \item Record absolute and relative error for every reported metric.
\end{enumerate}

Absolute and relative error should be reported as

\begin{equation}
e_{\mathrm{abs}} = |x_{\mathrm{est}} - x_{\mathrm{ref}}|
\end{equation}

\begin{equation}
e_{\mathrm{rel}}(\%) = \frac{|x_{\mathrm{est}} - x_{\mathrm{ref}}|}{|x_{\mathrm{ref}}|}\times 100
\end{equation}

    \item formalize a dual-path strategy for display signals versus analysis signals,
    \item add graph download support for every remaining analysis panel,
    \item create a benchmark dataset with expected values committed to the repository.
\end{itemize}

\section{Conclusion}
The current project has evolved from a basic oscilloscope file viewer into a broader desktop analysis workstation tailored to FNIRSI 1014D exports. The software now includes not only waveform reconstruction and standard measurements, but also current estimation, AC power, transfer analysis, correlation, cursor-based measurements, and export-focused reporting features. The most important engineering achievement of the current implementation is the alignment between the oscilloscope display and the reconstructed software waveform, since this visual fidelity directly affects user trust in every downstream analysis module.

Although the project still requires stronger automated validation and code modularization, the present state already constitutes a substantial engineering tool for laboratory use, experimentation, and academic documentation.
